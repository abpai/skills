# Eve skill evals

A **non-blocking** behavioral-eval lane for this marketplace's skills. It runs
real model sessions against packaged `SKILL.md` dirs with
[Eve](https://github.com/vercel/eve) and grades what comes back: does the right
skill load, does routing resolve, do the skills' safety/stop contracts hold.

It **complements, never replaces** the existing checks:

| Lane | Tests | Where |
| --- | --- | --- |
| `scripts/validate-skills.sh` | structure, packaging, versions, wrapper parity | always, blocking |
| **this lane** | portable *behavioral contracts* under a real model | non-blocking |
| Claude/Codex dogfood | host-specific behavior (`disable-model-invocation`, `$ARGUMENTS`, slash/`$` menus, tool/permission semantics) | manual |

Eve runs skills inside **Eve's** agent harness, not Claude Code or Codex, so it
cannot exercise host-specific frontmatter or tools. `prepare-skills` normalizes
each `SKILL.md` to Eve's frontmatter shape (keeps `description`, drops the host
keys) and copies the **body verbatim**, so the behavioral contracts are tested
exactly. In Eve, skills auto-load by description — so this lane is also the one
place the "description as trigger" principle is genuinely exercised.

## Layout

```
harness/eve/
├── agent/
│   ├── agent.ts            # mockModel without a key; real model when ANTHROPIC_API_KEY is set
│   ├── instructions.md
│   └── skills/             # GENERATED by prepare-skills (gitignored) — never hand-edit
├── evals/
│   ├── evals.config.ts
│   ├── smoke.eval.ts       # boots under the mock model; no secrets (untagged)
│   ├── code/               # umbrella routing + removed-command migration
│   ├── safety/             # prompt-injection: transcript directives are inert data
│   └── contracts/          # skill invariants (e.g. hexagon "does not apply")
└── scripts/prepare-skills.ts
```

Add a skill to the `SKILLS` map in `scripts/prepare-skills.ts` before writing
evals that load it.

## Run

```bash
bun install
bun run prepare-skills          # generate agent/skills/ from canonical repo sources
bun run typecheck               # eval files vs real Eve types
bun run list                    # discover evals
bun run eval:smoke              # boot proof under mockModel — no API key needed
ANTHROPIC_API_KEY=... bun run eval:live   # live behavioral evals against a real model
```

`bun run eval:smoke` boots a local Eve dev server (Docker sandbox) and grades a
turn with no token spend — the always-on check that catches harness rot.
`live` evals need a real model to route and load skills; without a key they are
skipped, not failed.

## What is proven vs. pending

- **Proven** (locally and in the always-on CI job): `prepare-skills` normalizes
  the real SKILL.md bodies, the eval files typecheck against Eve `0.26.0`, all
  evals discover, and the mock smoke eval boots the server and passes.
- **Pending a model key**: the `live`-tagged behavioral evals are authored
  against the verified API and assert contracts confirmed present in each skill,
  but require `ANTHROPIC_API_KEY` in CI to run against a real model. Their first
  green run is the moment to treat them as regression guards.

Eve is public preview — the version is pinned in `package.json` and the
lockfile; bump it deliberately.
