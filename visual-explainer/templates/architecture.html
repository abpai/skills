Authentication System

request lifecycle · 4 layers · 6 components

JWT-based authentication with refresh token rotation. The system handles login, token validation, session management, and rate limiting across a gateway + microservice architecture.

Overview

      flowchart TD
        client[Client] --> gateway[API Gateway]
        gateway --> auth[Auth Service]
        gateway --> api[API Service]
        auth --> db[(User DB)]
        auth --> cache[(Redis Cache)]
        api --> db

Component Details

Gateway Layer
API Gateway
Entry point for all requests. Validates JWT tokens on every request, enforces rate limits per client IP, and routes to downstream services. Handles CORS headers and request logging.
  • Express.js
  • helmet
  • rate-limiter-flexible
validates token
Auth Service
Authentication
Issues JWTs on login, validates tokens, handles refresh rotation. Tokens expire after 15 minutes; refresh tokens after 7 days. Stores active sessions in Redis for fast lookup.
  • jsonwebtoken
  • bcrypt
  • ioredis
API Service
Business Logic
Handles authenticated requests. Receives validated user context from the gateway. Each endpoint checks role-based permissions before executing.
  • Express.js
  • zod
  • prisma
persists data
Data Layer
User Database
PostgreSQL with Prisma ORM. Stores user credentials (bcrypt hashed), roles, and audit logs. Read replicas for query-heavy endpoints.
  • PostgreSQL 16
  • Prisma
Cache Layer
Redis Cache
Stores active sessions and refresh token hashes. TTL matches token expiry. Used for rate limiting counters per IP. Cluster mode in production.
  • Redis 7
  • ioredis
